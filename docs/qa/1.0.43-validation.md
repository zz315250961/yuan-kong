日期：2026-10-19。范围：Windows x64、Android arm64、网页账号/设备管理，以及 iPhone/iPad 控制端。当前线上版本仍为 1.0.42；本轮候选包与线上发布分开验收。

## 两指右键的复现与修正

用户报告：Android **触控模式**下两指双击无法触发右键。

在真实 Flutter 手势识别器与远程输入组件上重放触摸事件，修复前有三个确定失败：两指回调丢失坐标而返回 `(0, 0)`、快速连续两次双指轻触被吞、触控右键回调没有移动远程指针。手机触控模式还被旧处理条件明确排除。

修正后的交互：双指轻触一次即可右键，连续轻触也可识别；触控模式先以第一指落点定位，鼠标模式保持当前远程指针位置。两指手势在抬起第一指后认领事件，避免被其他识别器提前释放共享状态后抢走；单指序列不会释放其他识别器持有的状态。

回归命令（Flutter 3.24.5 / Dart 3.5.4）：

```powershell
cd flutter
flutter test --no-pub test/two_finger_right_click_test.dart --reporter expanded
flutter test --no-pub --reporter expanded
```

结果：14 项手势测试通过；当前全套 Flutter 测试 65 项通过，发布流水线用本轮重新生成的桥接再次通过。覆盖目标坐标、完整手势竞争、连续两次双指轻触、单指点击/双击/长按、缩放仍可工作、移动/取消/第三指/超时后恢复、阻挡区域和识别器销毁。

另在 Android 36 模拟器中的生产 `RawTouchGestureDetectorRegion` 回放连续两次双指轻触：触控模式 `right=2 / moves=2`，第一指局部坐标为 `(120,130)`；鼠标模式 `right=2 / moves=0`，两者均没有额外左键按下。该回放使用记录型 FFI，只证明 Android runtime 中从触摸事件到鼠标指令调用的链路，不等同于手机到远程系统菜单的端到端验收。

## 本轮功能和界面修正

- 手机/桌面统一“我的设备”，提供明确的连接与更多操作，改善窄屏、长名称、空列表、刷新和移除中的反馈。
- 连接页补空 ID/自连/重复开启保护；手机页面关闭后不继续更新已销毁状态；会话键盘、方向和定时器回调及时取消。
- 触控与鼠标两种模式的帮助均列出“双指轻触 → 右键”，说明字号跟随主题，切换器与滑杆随可用宽度调整。
- 网页修正改邮箱异步回调、错误密码提示、加载失败重试、刷新失败保留数据、重复提交、请求超时、表单可访问性与中间宽度布局。
- API 对畸形字段返回验证错误；正确解码设备标识；禁用账号的旧会话失效；SMTP 投递失败不再假报成功或占用重发冷却。
- iOS 构建从干净源码生成桥接，并校验品牌、版本、平台、架构、权限说明与图标。

网页视觉检查保留现有 LinkRemote 视觉，采用 impeccable 的针对性精修，完成一轮桌面/手机同批截图及一次确认。

## 帧率策略自动化边界

`python tests/run_video_policy_tests.py` 在 Windows 与 Linux 分别编译实际的 `video_policy.rs`、`bitrate_policy.rs` 和 `video_qos.rs`，每平台 23 项测试通过（CI run `39216636628`，提交 `a22643c`）。包含平台上限、用户帧率上限、延迟分级、自适应恢复窗口、码率倍率和 Android 最佳画质的全分辨率策略。QoS harness 仅对原生依赖提供桩，客户端帧率归一化、画质常量及 protobuf 数字值通过源契约检查防止漂移；该检查的 6 项回归也通过。

当前仍有需要在会话界面进一步明确的限制：自定义帧率滑块可请求 120，但 Android 被控端会忽略 61–120 的超限请求，而不是因此获得 120 帧。Android 仅“最佳”画质使用全分辨率，其他模式（包括自定义画质）沿用半分辨率策略。iOS/Android 作为控制端时能否实际解码、呈现 120 帧，不能由这些策略测试推断。

测试/CI 后续提交未改变候选标签 `v1.0.43` 的应用源码，也没有更改帧率默认值或生产配置。发布范围检查 10 项通过，分别验证候选应用内部版本一致性、稳定站点与稳定下载 manifest 一致性，允许候选领先尚未切换的线上版本。
