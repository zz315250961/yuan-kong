# 远控视频性能验收

本文定义 Windows x64 控制端连接 Windows x64 与 Android arm64 被控端时的可复现验收流程。每次候选发布必须先用未优化的 v1.0.35 在同一设备、同一网络、同一分辨率下记录基线，再测试候选版本。

## 测试矩阵

每个被控端在局域网以及 100 ms、250 ms、500 ms 注入延迟下分别运行以下场景 120 秒：

1. 静态文本：打开固定文档，保持窗口静止。
2. 连续滚动：以固定速度滚动同一网页。
3. 1080p 视频：播放同一段本地 1080p 视频。
4. 快速拖窗：连续拖动同一窗口覆盖屏幕四角。

Windows 和 Android 使用相同的控制端版本。Android 分别测试 Best、Balanced、Low；每次切换后等待采集器完成重建再开始计时。

## 记录字段

每次运行记录实际 FPS、目标 FPS、目标码率、QoS 区间、采集缩放、编码器/编解码格式、直连或中继、崩溃数、黑屏数、重连数。当前代码没有测量到的丢包率、编码器实际 FPS 或队列深度留空，不用推测值代替。

## 发布门槛

- 同场景实际 FPS 不低于 v1.0.35 基线的 95%。
- Android Best 报告 `Full`；Balanced 和 Low 报告 `1/2`。
- 60 FPS 会话的编码器目标为 60，不再固定为 30。
- 99/100/249/250/499/500 ms 样本进入预期 QoS 区间。
- 恢复必须连续取得三个 Good 样本。
- 不接受任何崩溃、黑屏或无限重连。

动态画质提升需通过同一场景录屏并排确认；目标码率增加本身不能替代视觉判断。未满足任一门槛时停止发布，附上场景、设备、网络条件和日志后回滚对应视频改动。
