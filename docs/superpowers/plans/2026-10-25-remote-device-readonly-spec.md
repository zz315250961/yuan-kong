# 受限远程操作下的“我的设备”只读入口

用户明确表示目前只能通过LinkRemote远控本机，要求保留必要安全保护、让“我的设备”能打开，验证通过后再更新下载并邮件通知。继续此前委托方案执行，不要求用户到本机开启权限。

## 方案与边界

协调者选择最小的只读例外：保留原首页buildRemoteBlock遮罩、远程输入判定和安全配置保护，在同一MouseRegion内的遮罩上提供清楚说明及“我的设备（只读）”入口。该入口始终以不可变readOnly=true打开既有设备面板，允许查看、刷新、重试和关闭，不允许连接其他设备、复制ID、删除设备或账号/权限/密码变更。面板请求沿用当前账号会话隔离，不暴露token，不触发设备注册心跳写入。

备选一（不采用）：远程开启“允许远程修改配置”，会扩大整个会话权限且用户无法本机确认。备选二（不采用）：把整个连接区域移出保护，会开放更多未请求操作。新入口只解决受限远程查看，不宣称修补所有既有远程保护的时序问题。

没有默认放宽权限、注册表或配置修改；设置页/连接管理器的保护调用保持原样。正常未受限路径及移动端默认设备操作保持现状。incoming-only不新增外连或此前不可见的设备入口，仅显示保护说明。原始已登录用户和设备列表保留，不重新登录或删除真实设备验收。

## 展现与测试

保护提示说明“远程配置保护已启用”和当前可用只读操作，不再只留无原因灰层。沿用现有蓝色、原生按钮与主题；700×600、1.3文字和明暗主题不溢出，安全子树不能通过鼠标或Tab绕过。罩层安全入口须始终位于同一MouseRegion内，不能因移入按钮触发onExit而闪烁。只读状态在弹窗生命周期内固定，主窗block恢复false不自动升级权限。

先用真实生产buildRemoteBlock和实际展示组件写失败测试，再最小实现：受限时原安全动作/键盘焦点仍被拦截，唯一入口可打开只读面板；只读卡片没有连接/复制/删除动作，正常模式不变；默认未提供例外的保护调用行为不变。对native FFI无法隔离部分如实注明，不增加测试专用全局bridge hook或复制假页面。
